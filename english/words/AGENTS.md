# AGENTS.md

## 项目用途

本项目用于整理和保存考研英语词汇训练中产生的知识点，便于后续查询和复习。

归档重点是：

- 单词的核心含义；
- 本次学习涉及的词性；
- 常用固定搭配；
- 有代表性的训练句；
- 单词在句子中的具体含义；
- 简洁的句子结构；
- 每日训练中的必要易错提醒。

本项目不用于完整保存聊天过程，也不用于记录或分析学习者的掌握程度、正确率、学习等级和复习状态。

## 专用 Skill

处理词汇训练记录时，使用：

```
$vocabulary-session-extractor
```

适用任务包括：

- 从 ChatGPT 会话、Markdown、文本或用户粘贴内容中提取词汇知识；
- 整理一次或多次词汇训练记录；
- 创建或更新单词详情；
- 创建或更新每日学习内容；
- 更新词汇目录；
- 合并同一单词在不同训练记录中的知识；
- 检查重复单词、重复句子和重复搭配。

具体的识别、提取、归档和去重流程，以该 Skill 的规则为准。

不要在 `AGENTS.md` 中重新实现 Skill 已经定义的工作流。

## 内容提取原则

词汇归档的核心目标是提取知识，不是复制学习过程。

应优先提取：

1. 当前训练实际涉及的核心词义；
2. 有使用价值的固定搭配；
3. 能体现单词用法的代表句；
4. 代表句的自然中文理解；
5. 句子的主要结构；
6. 单词在具体语境中的含义；
7. 对后续理解有帮助、适合写入每日训练记录的易错提醒。

默认不提取：

- 完整聊天记录；
- 任务说明；
- 鼓励性话语；
- 重复练习过程；
- 用户的每一次回答；
- 测试分数和正确率；
- A、B、C 或 L0—L4 等掌握状态；
- 学习稳定性和复习等级；
- 与知识整理无关的过程信息；
- 未在训练中实际涉及的大量词典内容。

用户的错误答案不得写成正确知识。

错误内容只有在具有复习价值时，才提炼为简短的易错提醒。

易错提醒只写入每日训练记录；单词详情文件不创建独立的“易错点”章节。

## 简洁原则

归档内容应保持简洁、清晰、便于复习。

不要为了显得完整而添加：

- 全部词典释义；
- 音标和词源；
- 大量派生词；
- 大量同义词；
- 冷门用法；
- 未实际训练的搭配；
- 大量相似例句；
- 过度细分的语法术语；
- 复杂的状态字段和元数据。

一个知识点已经能够清楚表达时，不要继续扩展。

## 单词整理原则

原则上，一个单词只维护一份详情文件。

同一个单词再次出现时：

- 更新已有内容；
- 补充新的词义、搭配或代表句；
- 不创建重复文件；
- 不重复添加已有内容。

只有能够可靠判断时，才将词形变化归入单词原形。

无法确定时，不得随意猜测。

## 句子整理原则

只保留具有代表性和复习价值的句子。

优先保留：

- 能体现目标词核心用法的句子；
- 包含重要固定搭配的句子；
- 能体现语境词义的句子；
- 用户曾经理解错误且值得复习的句子；
- 句子结构具有代表性的句子。

每个句子通常只需要：

1. 原句；
2. 参考译文；
3. 简洁的结构对照；
4. 相关搭配和语境词义。

不要逐词解释所有简单成分，也不要进行与目标词无关的复杂语法分析。

## 项目结构

所有操作均基于当前项目工作目录。

开始任务前先检查实际目录和已有文件。

如果项目已经存在自己的目录结构、模板或命名方式：

- 优先兼容现有结构；
- 不擅自整体重构；
- 不无故移动或重命名文件；
- 不为了套用模板而批量重写已有内容。

只有任务所需的文件或目录确实不存在时，才进行最小范围创建。

词汇目录采用分片结构：

- 根目录 `index.md` 只保存首字母导航和各分片单词数量；
- 实际单词目录保存在 `indexes/<首字母>.md`，使用表格呈现；
- 新增或更新单词时，只处理对应首字母分片，不读取全部目录。

单词详情中的“核心词义”统一使用“词性、核心含义”两列表格，每种词性独占一行，不得将多个词性聚合在同一行。

每日训练记录中的“新学单词”统一使用“单词、核心含义”两列表格，不使用项目符号列表；表格内的单词链接必须指向真实详情文件。每个单词仍只占一个表格行，“核心含义”单元格中的每项必须带词性；有多个词性时，以单词详情为准，使用 `<br>` 分行展示。

## 上下文与增量处理

同一学习会话可能持续多日，也可能与其他来源交替使用。处理训练来源时：

1. 按“专用连接器或 API → 来源专用 CLI/解析器 → 浏览器或人工导出”的顺序获取内容；只有依赖登录态、页面交互或解析器明确失败时才启用浏览器；
2. 按稳定来源名读取 `metadata/source-cursors.yml`；
3. 同一来源只将游标之后的新增内容送入提取任务，不把已归档历史重新放入模型上下文；
4. 来源只能完整获取时，先在模型上下文之外机械裁剪，再读取新增片段；解析失败时必须停止，不得静默回退为完整历史；
5. 将新增内容按结束总结拆成独立训练单元，一次只处理一个已完成单元，未完成尾部保留到下次；
6. 新链接可能仍来自既有长期会话时，先用全部已知消息 ID 和内容哈希匹配可复用边界；只有精确匹配才能裁剪；
7. 使用准确单元原文生成来源无关的内容指纹，避免同一训练内容从不同链接、导出或粘贴来源重复归档；
8. 切换来源时维护独立游标，切回旧来源后继续沿用旧游标；
9. 候选边界均不匹配时不得自动输出完整历史，必须先确认它确实是新来源；
10. 只有训练单元成功归档并通过统一验证后才推进游标，未完成片段不得跳过；
11. 游标可停在会话中任意已完成总结消息，不要求是会话最后一条消息；
12. 游标丢失、分支变化或内容哈希冲突时不得猜测，应先用已有记录核对并报告冲突。

状态文件随训练次数增长后，不得为了查询一个来源、记录或内容指纹而把完整元数据送入模型；使用 Skill 提供的查询脚本在模型上下文之外返回单项结果。追加型 Markdown、文本和导出文件采用“字节偏移＋前缀哈希”游标，历史前缀发生变化时必须停止。

一次归档多个单词时使用批量目录更新，只读取受影响的字母分片、每个分片最多写入一次，并只更新一次根目录。

## 修改原则

执行任务时：

1. 先读取相关现有文件；
2. 只修改与当前任务直接相关的内容；
3. 优先局部更新；
4. 保留用户人工添加和修改的内容；
5. 不覆盖无法确认用途的章节；
6. 不批量格式化无关文件；
7. 不删除与当前任务无关的内容；
8. 不修改当前项目工作目录之外的文件。

如果新内容与已有内容存在冲突，应保留已有内容并在结果中说明，不得静默覆盖。

## 去重要求

词汇归档任务必须能够安全重复执行。

相同内容再次处理时，不得重复产生：

- 单词详情文件；
- 单词目录项；
- 相同词义；
- 相同固定搭配；
- 相同代表句；
- 相同易错提醒；
- 相同每日训练内容。

相同任务第二次执行时，应尽量不产生新的文件差异。

## 文件要求

除非项目已有其他明确规范：

- Markdown 和 YAML 使用 UTF-8；
- 相对路径使用 `/`；
- Markdown 链接必须指向真实文件；
- YAML 必须保持合法；
- 不写入无意义的尾随空格；
- 不引入无关的第三方依赖；
- 不生成与学习档案无关的文件。

## Git 边界

除非用户明确要求：

- 不创建 Git commit；
- 不执行 push；
- 不创建 Pull Request；
- 不切换分支；
- 不执行破坏性 Git 命令；
- 不删除未跟踪文件；
- 不回滚用户已有修改。

可以查看 Git 状态和差异，以确认本次修改范围。

## 完成检查

任务结束前检查：

- 是否使用了 `$vocabulary-session-extractor`；
- 是否只提取了有复习价值的知识点；
- 是否混入了掌握状态和无关过程记录；
- 是否存在重复单词、句子或搭配；
- 单词详情中的“核心词义”是否每种词性独占一行；
- 每日记录中的“新学单词”是否使用两列表格，且“核心含义”是否标注词性并按需使用 `<br>` 分行；
- 是否只读取和更新了相关字母目录分片；
- 是否只处理了持续来源中游标之后的新增内容；
- 是否一次只处理一个已完成训练单元，并保留未完成尾部；
- 是否使用准确单元原文计算并检查来源无关内容指纹；
- 是否只查询所需元数据片段，没有加载完整状态文件；
- 多词归档是否采用批量目录更新；
- 是否运行统一归档验证脚本；
- 是否保留了人工内容；
- 是否只修改了当前任务相关文件；
- Markdown 链接和结构化文件是否有效。

## 完成报告

完成后简要说明：

- 处理了哪些训练记录；
- 新增了哪些单词；
- 更新了哪些已有单词；
- 创建或更新了哪些文件；
- 是否完成去重和链接检查；
- 是否存在无法确定的词义、词形或内容冲突。

不要输出冗长的内部执行过程。
