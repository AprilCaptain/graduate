# 词汇训练归档

从训练记录中提炼可长期复习的词汇知识，只在当前项目工作目录及其子目录内执行兼容现有结构的幂等更新。不要复制完整聊天，不要把档案扩写成词典。

## 开始前

1. 将当前项目工作目录视为词汇档案根目录；不要硬编码绝对路径、用户名、操作系统路径或仓库名称。
2. 读取根目录中的 `AGENTS.md`（如存在），并遵守其约束。
3. 确认用户指定的文件、文本、日期、章节或批次范围。用户明确指定范围时，不要扩大处理范围。
4. 检查现有目录和文件格式。优先兼容现有结构；不要移动档案、整体重构或为套用模板覆盖文件。
5. 仅读取用户直接提供或明确指定的来源。用户粘贴的内容将来源记为 `pasted-chat-record`；文件来源使用项目内相对路径。
6. 读取 `metadata/source-cursors.yml`。同一来源再次出现时，先在模型上下文之外按游标裁剪已处理前缀，只将游标之后的新增消息交给提取流程；来源改变时使用独立游标，不覆盖旧来源状态。

## 选择参考规则

- 识别一个或多个训练单元、训练完成状态和日期时，读取 [references/source-detection.md](references/source-detection.md)。
- 提取新词、复习词、词义、搭配、句子和有复习价值的错误时，读取 [references/extraction-rules.md](references/extraction-rules.md)。
- 创建或更新每日文件、单词文件、目录、状态文件时，读取 [references/archive-schema.md](references/archive-schema.md)。
- 写入前后执行 [references/validation-checklist.md](references/validation-checklist.md)。
- 仅在缺少兼容的现有格式时，复制并调整 `assets/` 中的模板；不要把模板机械覆盖到已有文件。

## 执行流程

1. 准备增量输入。按“专用连接器或 API → 来源专用 CLI/解析器 → 浏览器或人工导出”的顺序获取来源；只有需要登录态、交互或前两种方式失效时才使用浏览器。ChatGPT 分享页使用 `scripts/extract_chatgpt_share.py`，追加型 Markdown、文本或导出文件使用 `scripts/extract_incremental_text.py`。重复来源用游标裁剪，解析器结构不匹配时必须失败，不得把完整历史回退送入模型。
2. 识别训练单元。先用 `scripts/split_training_units.py` 在模型上下文之外寻找“本次学习记录”“今日学习记录”“学习总结”等结束总结，只将一个已完成单元交给提取流程；未完成尾部保留到下次。不要要求 `VOCAB_SESSION_START`、`VOCAB_SESSION_END` 或 `VOCAB-*` 编号。
3. 将同一来源中的多次训练拆为独立单元。无法可靠划分时，只处理可确认部分并报告不确定项。
4. 按来源证据确定每个单元的训练日期。不要用当前日期、文件创建时间或修改时间猜测。
5. 日期或完成状态无法确认时，仅准备待确认草稿或报告；不要登记为正式完成记录。
6. 对每个可归档单元运行 `scripts/generate_record_id.py --output json`，使用准确的单元原文生成稳定的 `record_id` 和来源无关的 `content_fingerprint`。输入自带批次编号时另存为外部标识，不要替代内部 ID。
7. 使用 `scripts/query_metadata.py` 查询目标来源、记录或内容指纹；不要把不断增长的完整元数据文件送入模型。随后只读取目标每日文件、相关单词详情和待变更单词对应的目录分片，以 `record_id` 和 `content_fingerprint` 检查同源重放、跨来源重复或内容更新。
8. 从详细训练过程提取内容，再用结束总结校验日期、范围、数量、薄弱词和复习事项。不要只复制总结表。
9. 仅在上下文可靠时归并词形。保留无法确认的来源词形或列为待确认，不要猜测词元。
10. 先创建或最小更新单词详情，再更新当日训练章节。单个词用 `scripts/update_index.py`，多个词用 `scripts/update_indexes_batch.py`，保证每个受影响字母分片只读写一次、根目录只更新一次。确保写入的链接真实存在。
11. 更新每日文件后运行 `scripts/update_daily_reviews.py --date YYYY-MM-DD`，按第 1、2、4、7、15 个实际学习日生成文件级“今日复习”。补录旧日期或回填历史时使用 `--all` 重算全部受影响日期；检查幂等性时追加 `--check`。不要手工推算自然日或复制历史内容。
12. 保留人工备注、译文、释义、章节、标签和非标准但有效的内容。只补充缺失或有新证据的部分，不要整文件重写。
13. 运行 `scripts/validate_archive.py`，检查今日复习计划、重复句子、搭配、单词条目、分片计数、链接、Markdown、YAML、元数据边界和本次文件差异。
    修改本 Skill 的 `scripts/` 后，另运行 `python3 -m unittest discover -s .agents/skills/vocabulary-session-extractor/tests -p 'test_*.py'`；日常归档无需重复运行该回归测试。
14. 所有内容文件成功写入且验证通过后，使用 `scripts/finalize_metadata.py` 写入归档状态并将来源游标推进到已成功归档单元的结束总结消息。脚本会拒绝重复内容指纹、陈旧游标和不一致元数据；相同任务再次执行应产生零文件差异。

## 更新原则

- 同一天只使用一个日期文件，以“第1次训练”“第2次训练”区分独立训练；将 `record_id` 存为 Markdown 注释。
- 每日文件在首个训练章节前只保留一个“今日复习”。实际学习日必须有正式 `record_id` 和训练章节；按日期序列向前取第 1、2、4、7、15 个学习日，以未完成任务和单向相对链接列出，最早学习日写“暂无需复习内容。”。保留用户已勾选的同目标任务，不把勾选状态写入 YAML 或元数据。
- 单词详情的“核心词义”使用“词性、核心含义”两列表格，每种词性独占一行，不将多个词性聚合在同一行。
- 每日训练记录的“新学单词”使用“单词、核心含义”两列表格，不使用项目符号列表；每个单词只占一个表格行，“核心含义”中的每项带词性，多词性时以单词详情为准并使用 `<br>` 在同一单元格内分行。
- 每日训练记录的每条“代表性训练句”同时包含完整英文原句和自然准确的中文译文，按 `1. **原句**：...<br>` 与下一行 `**译文**：...` 的统一格式展示；不得只写英文原句。
- 已有 `record_id` 执行校验与补全，不要重复追加或改变既有训练顺序。
- 单词详情原则上按可靠原形唯一归档；已有单词仍可追加本次新词义、搭配、句子和学习记录。
- 用户错误答案只转化为每日训练记录中的易错提醒；单词详情不创建独立的“易错点”章节，正确知识采用最终确认的讲解。
- 不记录或推断正确率、掌握等级、学习稳定性和复习等级；“今日复习”的任务勾选只表示任务是否完成。
- 新词数量与可确认单词不一致时，不要虚构条目；归档可确认内容并报告差异。
- 状态文件只记录成功完成的归档。日期未确认的草稿不得标记为 `completed`。
- 来源游标只在训练单元成功归档后推进。未完成片段保留在游标之后，以便下次与新增消息一起处理；状态同时保存边界类型、起止哈希和单元消息数量或字节范围，便于审计与故障定位。

## 完成报告

简要说明识别的训练次数与日期、新增和更新的单词数量、创建或更新的每日文件及今日复习、目录分片、归档状态与来源游标是否更新、数量差异、不确定项，以及重复、链接和格式检查结果。不要输出冗长的内部推理。
