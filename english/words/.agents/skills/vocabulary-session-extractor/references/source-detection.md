## 范围优先级

按以下顺序确定处理范围：

1. 使用用户明确指定的文件、文本、日期、训练、章节或已有批次编号。
2. 在指定来源中查找结构化结束总结。
3. 使用明显的训练开始和结束表达辅助划界。
4. 用户明确说明全部内容是一场训练时，将完整内容视为一个候选单元。

不要越过用户指定范围扫描其他文件或日期。可选的 `VOCAB_SESSION_START`、`VOCAB_SESSION_END`、`VOCAB-YYYYMMDD-NN` 或手工编号只能辅助识别，缺少它们时继续处理。

## 持续来源的增量输入

先用稳定来源名查询 `metadata/source-cursors.yml`，再决定输入范围：

1. 同一链接、文件或会话再次出现且游标存在时，只提取游标之后的消息或文本。
2. 优先使用连接器、API 或 CLI 原生的 `after`、消息 ID、时间戳或分页游标；若来源只能完整获取，先在模型上下文之外机械裁剪，再把新增片段送入模型。
3. ChatGPT 分享页可将原始 HTML 通过标准输入交给 `scripts/extract_chatgpt_share.py`，使用 `last_message_id` 和 `last_message_sha256` 验证并裁剪。不要打印或读取完整 HTML 后再让模型自行寻找新增部分。
4. 游标不在当前分支、游标消息内容哈希变化或来源被编辑时，不要静默重放全部历史。先用已有 `record_id`、日期和结束总结核对；仍无法安全定位时报告冲突。
5. 新来源没有自己的游标时，先在模型上下文之外用所有已知来源的消息 ID 与内容哈希做候选边界匹配。若新链接实际指向同一长期会话，使用最靠后的精确匹配边界裁剪；不得仅凭会话标题、日期或词数判断为同一来源。
6. 候选边界均不匹配时，将其视为待确认的新来源；只有确认不存在可复用边界后，才允许把该来源的完整指定范围送入模型。
7. 来源切换时为新来源创建独立游标；用户以后切回旧来源时继续使用旧来源自己的游标。
8. 只有完成归档并通过验证后，才把游标推进到该训练单元结束总结对应的最后一条消息。未完成片段不得越过。

若游标之后没有新内容，直接报告无新增训练，不读取既有每日文件、单词详情或目录分片。

## 训练单元识别

优先识别语义相近的总结标题或内容：

- 本次学习记录
- 今日学习记录
- 本次训练记录
- 词汇训练总结
- 今日训练总结
- 学习总结

结构可以是 Markdown 表格、列表或自然语言。将结束总结视为训练完成的强证据，并用它确认日期、训练范围、新词数量、薄弱词、问题和下次复习。具体知识仍从该总结前方对应的详细训练过程提取。

将“开始今天学习”“开始词汇训练”“今天先学到这里”“结束今天的词汇训练”“生成学习记录”“本次训练完成”等表达仅用作辅助信号，不要求完全匹配。

## 多次训练拆分

同一来源中存在多个结束总结时：

1. 将每个总结关联到其前方最近、尚未归档的训练过程。
2. 保持不同日期彼此独立，不要把前一天内容合入下一天。
3. 允许同一天有多个单元，不要互相覆盖或只按词数去重。
4. 不要把多场训练的词数相加后伪装为一次训练。
5. 保留原始顺序。只有边界有可靠证据时才拆分。
6. 对边界模糊的片段保留原内容并报告；不要强行分配。

## 完成状态

具有结束总结、明确结束表达，或用户明确声明为完整训练的单元可视为已完成。只有零散练习且无法确认是否结束时：

- 提取可供用户确认的草稿或列出识别结果；
- 不写入正式完成状态；
- 不因缺少“本次学习记录”而直接拒绝；
- 在报告中说明使用的替代依据或待确认点。

## 训练日期

按以下证据优先级确定日期：

1. 结束总结中的结构化日期；
2. 用户明确指定的训练日期；
3. 训练内容中的明确日期标题；
4. 可靠的会话日期信息；
5. 已有归档上下文能够唯一确定的日期。

将日期规范化为 `YYYY-MM-DD`。不要使用 Codex 当前日期、文件创建时间或修改时间推断训练日期。证据冲突时优先结构化总结日期，保留冲突说明，不要静默覆盖。日期仍无法确认时只生成草稿，不创建正式日期文件、不生成正式 `record_id`、不登记 `completed`。

## 来源名称

- 用户直接粘贴：使用 `pasted-chat-record`。
- 用户指定项目文件：使用相对于项目根目录的路径。
- 其他有名称但无路径的来源：使用稳定、简洁的来源名称。

不要虚构路径，不要在档案中保存用户计算机的绝对路径。文件修改时间不是来源日期证据。
